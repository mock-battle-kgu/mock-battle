# 게임 설계

> **[확정]** 팀에서 결정한 내용 / **[초안]** 제안 단계로 팀 논의 후 확정 필요

## 1. 개요 [확정]
- 주제: 모의투자 배틀
- 한 줄 소개: 참가자끼리 같은 시장에서 겨루는 웹 기반 실시간 모의투자 게임
- 차별점: 기존 서비스는 모두 혼자 또는 1:1로 차트와 싸우는 구조. 모의투자 배틀은 참가자끼리 서로의 판단과 가격에 영향을 주는 구조

| 비교 대상 | 기간 | 인원 | 상대 |
|---|---|---|---|
| 증권사 모의투자 | 몇 주 ~ 몇 달 | 혼자 | 실제 시장 |
| 블라인드 차트 게임 (차트퀘스트, Market Rush 등) | 한 판 수 분 | 혼자 또는 1:1 | 과거 차트 |
| **모의투자 배틀** | **10분 단판** | **최대 8명** | **다른 참가자** |

## 2. 핵심 기능 [확정]

### 2-1. 최대 8인 실시간 방 대결
- 방장이 방을 만들면 PIN이 생성되고, 참가자는 PIN을 입력해 입장
- 서버가 만든 시세를 모든 참가자에게 동시에 전송 (누구도 먼저 보거나 늦게 보지 않음)
- 매매할 때마다 수익률을 다시 계산해 순위를 실시간 표시

### 2-2. 루머 카드 심리전
- 참가자는 게임 중 루머 카드를 사용해 다른 참가자 화면에 '속보' 뉴스를 띄울 수 있음
- 루머는 시스템이 내보내는 실제 뉴스와 같은 모양이라 구별할 수 없음
- 게임 종료 후 어떤 뉴스가 루머였고 누가 퍼뜨렸는지 공개

### 2-3. 플레이어가 움직이는 시장
1. 모든 참가자의 매수·매도 주문을 게임 서버가 모음
2. 일정 시간 동안의 순매수량(매수량 − 매도량)을 계산
3. 시세 엔진 가격에 순매수량만큼 보정 → 몰려 사면 오르고, 몰려 팔면 떨어짐
- 이로 인해 가능한 플레이: 담합(같이 사서 끌어올리기), 작전(루머 + 매수), 배신(같이 사자 해 놓고 먼저 팔기)

## 3. 게임 모드 [확정]
| 모드 | 인원 | 시세 | 비고 |
|---|---|---|---|
| 대결 모드 (메인) | 2~8명 | 시세 엔진이 생성한 가상 시장 | 핵심 기능 3가지 모두 적용 |
| 연습 모드 | 1명 | 실제 과거 주가, 종목명·날짜 숨김 | 종료 후 종목·시점 공개 |

## 4. 게임 규칙 [초안]
| 항목 | 제안 값 |
|---|---|
| 한 판 시간 | 10분 |
| 시작 자금 | 가상 자금 1,000만 원 |
| 종목 | 가상 기업 6개 |
| 루머 카드 | 1인당 2장 |
| 루머 효과 | 처음에는 화면에 뉴스로만 표시, 가격에는 직접 영향 없음 |
| 플레이어 영향 반영 | 최근 10초 순매수량 기준으로 가격 보정 |
| 승패 | 게임 종료 시 총자산(현금 + 보유 주식 평가액) 순위 |

## 5. 시세 규칙 [초안]
| 모드 | 가격 갱신 | 캔들 1개 | 한 판 캔들 수 |
|---|---|---|---|
| 대결 모드 | 1초마다 | 5초 (가격 5개 묶음) | 약 120개 |
| 연습 모드 | - | 실제 하루, 약 2.4초 | 약 250개 (1년치) |

## 6. 시스템 구성
Docker Compose로 컨테이너 6종 구성

| 컨테이너 | 역할 |
|---|---|
| Nginx | 화면 제공, 요청 분배 |
| 게임 서버 | 방 관리, 주문 체결, 실시간 순위, 루머 카드 |
| API 서버 | 게임 결과 저장, 랭킹 |
| 시세 엔진 | 가격 생성(대결), 과거 주가 재생(연습), 플레이어 영향 반영 |
| RabbitMQ | 시세 엔진 → 게임 서버 메시지 전달 |
| DB | 게임 결과 저장 (볼륨으로 영구 저장) |

데이터 흐름: 시세 엔진 → RabbitMQ → 게임 서버 → (Socket.IO) → 참가자 화면 / 게임 종료 시 게임 서버 → API 서버 → DB

## 7. 활용 오픈소스
| 오픈소스 | 용도 |
|---|---|
| Socket.IO | 실시간 시세·순위 전송 |
| RabbitMQ | 시세 메시지 큐 |
| Lightweight Charts | 캔들 차트 |
| k6 | 동시 접속 부하 테스트 |

## 8. 미정 사항
- [ ] 랭킹 방식: 닉네임 + 명예의 전당(역대 한 판 최고 수익률) / 회원 가입 + 누적 랭킹
- [ ] 기술 스택 확정 (제안: React, Node.js)
- [ ] Kubernetes 적용 여부
- [ ] 추가 기능: AI 봇 참가자 (통합 테스트에 재사용 가능)
- [ ] 팀원별 역할 배정
